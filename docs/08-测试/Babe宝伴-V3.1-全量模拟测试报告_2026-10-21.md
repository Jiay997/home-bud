## 3. 多智能体协作功能验证

### 3.1 PRD 口径（V3.0 §6.3 / §6.8 / F6 / F12）

- 编排器 + 领域 Agent（育儿/宠物）+ 风险控制服务；家庭综合入口**必须同时执行 3 个领域 Agent**（AC-F6-08-1）。
- 单领域问题**不得引入无关 Agent**（JR-3）。
- 安全分节 `pinned=true`，不可折叠/下移，**不参与权重排序**（GR-4）。
- 每次请求须可追溯：命中意图、调度决策、各 Agent 输出、耗时、风险判定、引用 kb_id、模型与版本、**权重版本**（GR-10 / AC-F12-06-1）。

### 3.2 实测证据

会话详情（接口）：`agents_involved=[child, pet, safety]`、`render_order=[safety, child, pet]`、安全分节 `pinned=true`。
结论：AC-F6-08-1、GR-4 在**接口契约层通过**；帧序列完整（started → 分节 delta×3 → done×3 → completed），首帧 42ms。

**（2）单领域问题：不引入无关 Agent**

实测育儿会话 `75c5c2d8-a39a-44db-86cc-bafac3ae0647`（问题："2岁宝宝体温37.8度，精神状态好，要不要去医院"）：`agents_involved=["child","safety"]`，`render_order=["safety", …]`，**未出现 pet**。
运营端调用日志中单领域会话仅记录 `intent_route / triage / retrieve / child_agent / safety_agent` 五个节点（如会话 97）。
结论：JR-3 通过。

### 9.2 主要风险点（按优先级）

1. **安全分诊正确性（D-02 / D-03 / D-07）**：未绑定档案时把 2 岁低热套用"<3 月龄"红档规则，且分诊规则 0 签署即对外生效。前者会误导家长就医决策，后者是合规门禁失守，两者叠加使"分级正确率"无法对外承诺。建议先冻结档位对外发布，再修复年龄解析（从问题文本抽取月龄/年龄，缺失时按"信息不足"走黄档，而不是让高优先级红规则无条件命中）。
2. **高危求助渠道不可用（D-01）**：拦截页是产品最关键的兜底界面，热线缺失将直接削弱救助价值，且 E2E-22 已是未通过状态。建议将"必备渠道核验"作为发布硬门禁，并在号码未核验时至少展示 110/120 与"立即联系身边成年人"的可执行指引。
3. **商业化闭环不可用（D-04）**：H5 展示价格与购买按钮但无法支付，属"可点但不可用"，建议按平台能力隐藏入口（对齐 AC-F9-03-1 的 iOS 处理方式），或明确标注"当前平台暂不支持购买"。
4. **运营治理能力缺口（D-05 / D-06）**：权重配置缺失、日志无法还原各 Agent 输出摘要与权重版本，导致"调优—验证—回滚"闭环不成立；这也是多智能体协作质量无法量化的根因。建议补齐 F12.7 与 AC-F12-06-1 字段后再做真实模型回归。
5. **内容与配置未就绪（D-08 / D-09 / D-10 / D-11）**：提醒任务、订阅消息模板、专题包、测评文案均处于未就绪状态，用户侧感知就是"空态 + 占位"。建议在发布前统一跑一次"内容就绪清单"。
6. **环境与工程（D-17 / D-14）**：后台端口写死导致本地环境不可复现；768 宽度表格不可用。建议端口可配置 + 启动前置检查，后台表格增加 `scroll-x` 或响应式列。

- **测试基线补强**：在 CI 中固化 `L0` 冒烟（登录/同意/提问/分诊/长图/后台登录/知识库发布），并把"渠道核验、规则签署、AI 标识占比"三门禁接入发布流水线。
