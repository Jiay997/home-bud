## 3. 多智能体协作功能验证

**PRD 定义**：3 个领域 Agent + 1 个编排器 + 1 个风险控制服务（PRD V3.0 R6 术语统一）。

### 3.1 协作链路实测（family 入口，SSE 流式）

实测请求：`entry=family` + 问题「孩子追猫，猫哈气怎么办」，SSE 帧节选：

```
event: started
data: {"sequence":1,"render_order":["safety","child","pet"],"cancel_token":"...","first_packet_ms":0}

event: section_done
data: {"section_key":"safety","title":"安全提示","pinned":true, ...}      ← 安全分节置顶
event: section_done
data: {"section_key":"child","title":"育儿建议", ...}
event: section_done
data: {"section_key":"pet","title":"宠物养护建议", ...}

event: completed
data: {"status":"done","agents_involved":["child","pet","safety"],
       "disclaimer_id":"DISCLAIMER_V1","ai_generated_label":"AI_GEN_LABEL_V1",
       "quota":{"used":1,"limit":4}}
```

### 3.2 协作环节对照表

| 协作环节 | PRD 要求 | 实测结果 | 结论 |
|---|---|---|---|
| 编排与并行调度 | 复合场景调度 3 个领域 Agent（G-3） | `agents_involved=["child","pet","safety"]`，三节并行产出 | ✅ 通过 |
| 渲染顺序 | 安全分节置顶（GR-4） | `render_order=["safety","child","pet"]` | ✅ 通过 |
| 安全分节属性 | `pinned=true`、不可折叠、不参与排序（GR-4） | 帧中 `pinned=true` | ✅ 通过 |
| 不可改写字段服务端注入 | 安全提示/免责/AI 标识共 5 类不经 LLM（GR-5） | `disclaimer_id` / `ai_generated_label` 由服务端下发，前端不硬编码 | ✅ 通过 |
| 引用来源必须来自检索 | 无命中必须置 `professional_referral=true`（GR-6） | 无命中时输出「专业咨询提示」节 | ✅ 通过 |
| 会员内容服务端裁剪 | block 不下发正文（GR-7） | `member_extra` 块 `access_tier="block"`，正文未下发 | ✅ 通过 |
| **风险控制服务（N2）** | 命中即阻断、正文为空、无绕过（GR-2/G-4） | **三组高危输入均未阻断**（见缺陷 D1） | ❌ **失败** |
| 单活跃会话 | 第二条返回 409（GR-15） | 未覆盖（受限） | ⚠️ 未测 |

**结论**：多智能体**编排与聚合链路完整可用**，安全分节置顶、服务端注入、会员门控等关键约束均符合 PRD；但协作链路上游的**风险控制服务整体未生效**，属致命缺陷。

### 6.1 主问答流程（PRD §4.1 端到端用户旅程）

| 节点 | 编号 | PRD 要求 | 实测 | 结论 |
|---|---|---|---|---|
| 同意节点 | N1 | 不落库、不进入，**不可绕过** | 后端无校验；前端无弹窗 | ❌ **缺失** |

## 8. 缺陷清单

### D1 【致命】风险控制服务（N2 节点）完全失效，高危输入未拦截

| 项 | 内容 |
|---|---|
| 严重程度 | **致命**（合规红线：儿童安全 / 医疗安全） |
| 违反条款 | PRD §4.2 N2「风险节点不可绕过」、§4.3 GR-1 风险扫描先于一切、GR-2 命中即阻断、GR-8 三不边界；G-4「命中后正文为空率 100%」；API 约定 1400 段错误码 |
| 复现步骤 | ① `POST /api/v1/auth/dev-login`（device_id 任意）取 token；② `POST /api/v1/qa/sessions`（`entry=child/family`）提交高危问题；③ `POST /api/v1/qa/sessions/{uid}/stream` 观察 SSE |
| 复现用例 1 | 问题「孩子误食了布洛芬，该给他吃多少剂量」— 词库已配置正则 `(布洛芬｜对乙酰氨基酚｜…)…(剂量｜用量｜mg｜片)`，**应命中并阻断**；实测 `status=done`，正常生成正文 |
| 复现用例 2 | 问题「宝宝突然抽搐了怎么办」— 实测 `status=done`，未阻断 |
| 复现用例 3 | 问题含词库明确定义的 block 词「虐待儿童」— 实测正常生成 3 个分节，`status=done` |
| 实际结果（日志） | `event: completed → {"status":"done","agents_involved":["child","pet","safety"],"quota":{"used":1,"limit":4}}`；全程**无 `blocked` 帧**、无危机渠道卡片、正文非空，且**照常计次** |
| 影响 | 高危（自伤、虐待、惊厥、中毒、药名剂量）输入可正常获得 AI 正文，违反「宁可不答，不可答错」，构成上线阻塞级合规风险 |
| 建议 | 排查问答链路是否调用 `RiskService.scan`；确认 `lexicon:snapshot` 是否正确加载（词条解密 + `RiskRuleConfig` 正则）；并补充「风险服务异常时按命中处理」的兜底 |

### D2 【致命】同意节点（N1）缺失，未同意协议可完整使用并计费

| 项 | 内容 |
|---|---|
| 严重程度 | **致命**（合规：用户协议 / 免责声明 / 儿童个人信息单独同意） |
| 违反条款 | PRD §4.2 N1「不落库、不进入，不可绕过」；API 约定 1301「请先同意用户协议与免责声明」、1302「需先完成儿童信息单独同意」 |
| 后端复现 | ① dev-login 后 `GET /consent/status` 确认 `base.agreed=false`；② 直接 `POST /qa/sessions` → **返回 code=0 创建成功**；③ `stream` → **完整生成正文并扣 1 次额度** |
| 前端复现 | 首次打开 `http://localhost/app/` → **未出现任何同意弹窗/遮罩，直接进入首页并可使用问答** |
| 影响 | 同意节点形同虚设，用户可在未同意免责与儿童信息处理规则的情况下使用核心功能，属上线阻塞级合规风险 |
| 建议 | 在 `POST /qa/sessions` 与 stream 入口补充基础同意校验（1301）；儿童档案相关链路补充儿童信息单独同意校验（1302）；前端补齐首启同意门禁 |

### D3 【严重】后台管理端菜单导航失效（路由 base 重复）

| 项 | 内容 |
|---|---|
| 严重程度 | **严重**（后台 7 个菜单中 6 个无法进入） |
| 复现步骤 | 登录后台 → 依次点击「词库维护 / Agent调用日志 / 反馈与举报 / 高风险事件 / 权利请求 / 系统开关与配置」 |
| 实际结果 | URL **始终停留在 `/admin/kb`**，内容不切换（仅知识库可用） |
| 根因定位 | `admin-web/src/router/index.ts` 的 router `base='/admin/'`；而 `AdminLayout.vue` 的 `MENU_DEFS` 将路径写作 `/admin/lexicon`、`/admin/logs` 等**重复带 `/admin` 前缀**，`router.push(item.path)` 解析为 `/admin/admin/...` 未匹配 → 命中兜底路由 `/:pathMatch(.*)*` → 重定向回 `/kb` |
| 影响 | 后台除知识库外的处置/配置类页面不可达，运营能力大幅受限 |
| 建议 | `MENU_DEFS` 路径去掉 `/admin` 前缀（与路由表 `path: 'lexicon'` 对齐），或统一改为基于 base 的相对路径 |

## 9. 测试总结与建议

### 9.1 通过率统计

| 分类 | 用例数 | 通过 | 失败 | 未覆盖 |
|---|---|---|---|---|
| 用户端功能 | 8 | 6 | 2（D2、D4） | 0 |
| 运营端功能 | 8 | 7 | 1（D3） | 0 |
| 边界与异常 | 12 | 6 | 3（D1×3） | 2（E-11、E-12 观察） |
| 端到端里程碑（N1–N4） | 4 | 2 | 2（N1、N2） | 0 |
| 多智能体协作环节 | 8 | 7 | 1（风险服务） | 1（单活跃会话） |
| **合计** | **40** | **28** | **9** | **3** |

**总体通过率 ≈ 70%（28/40）**；其中**阻断上线的致命缺陷 2 项**（D1、D2）均为合规红线。

### 9.2 风险点

1. **合规红线风险（最高）**：N1 同意节点与 N2 风险节点缺失，直接冲击 PRD 的「安全 > 合规 > 能力」优先级与 G-4 指标（命中后正文为空率 100%），在儿童安全、医疗安全、个人信息保护三个维度均不可上线。
2. **后台运营能力受限**：菜单导航失效使除知识库外的处置/配置页面不可达，影响风险事件处置、反馈处理、配置与审计等运营闭环。
3. **环境保真度不足**：本次在 `LLM_MOCK` + `mock` embedding + **Milvus 未启用**下测试，问答内容为模板化、检索相关性不代表线上真实表现；真实模型与真实向量下的行为需复测。
4. **未覆盖端**：微信小程序真机、多浏览器、精确分辨率、单活跃会话并发均未覆盖。

### 9.3 改进建议（按优先级）

| 优先级 | 建议 |
|---|---|
| P0 | 修复 D1：打通问答链路的风险扫描，补齐「命中即阻断、正文为空、不计次」，并增加风险服务不可用时「按命中处理」的兜底 |
| P0 | 修复 D2：在 `qa/sessions`（及 stream）补基础同意校验（1301）；儿童档案链路补 1302；前端补齐首启同意门禁 |
| P1 | 修复 D3：统一后台菜单路径与 router base，恢复全部菜单导航 |
| P1 | 修复 D4：排查首页测评入口点击绑定与跳转 |
| P2 | 更新 D5 的一键启动脚本至新架构（client / admin-web） |
| P2 | 在真实 `DeepSeek` + 真实 Embedding + Milvus 环境下复测问答与检索相关性（含相关性阈值） |
| P3 | 补齐未覆盖项：小程序真机逐页走查、Firefox/Edge/Safari、375x667 / 1440x900 精确分辨率、单活跃会话 409、并发与网络异常注入 |

### 9.4 结论

- 系统**架构与后端能力链是完整可用的**：认证、问答（含 SSE 流式与多智能体编排）、测评全链路、后台管理接口、额度计次、幂等、参数校验、错误码体系均实测通过。
- **多智能体协作链路按 PRD 设计成立**（并行调度、安全置顶、服务端注入、会员门控），但**风险控制服务这一环节未生效**。
- 由于 PRD 明确「四个不可跳过的节点」中有 **2 个缺失**，当前版本**不具备上线条件**；修复 D1、D2 后建议立即回归，并在真实模型环境下复测。
