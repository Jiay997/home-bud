## 3. 多智能体协作功能验证

### 3.1 PRD 口径

- V3.0 AC-F6-08-1：用户显式选择“家庭综合问答”入口后，无论是否识别为复合场景，都必须执行育儿、宠物、家庭安全三个 Agent。
- V3.0 AC-F6-01-1/2：复合场景输出三节，顺序由服务端 `render_order` 决定。
- V3.0 AC-F6-02-1：安全分节 `pinned=true`，不可折叠、不可下移、不参与权重排序。
- V3.0 JR-3：单领域问题不得引入无关 Agent。

## 8. 缺陷清单

### D-01 H5 账号头像上传成功但不展示（严重）

| 项 | 内容 |
|---|---|
| 复现步骤 | 1. `POST /me/avatar` 上传 PNG，返回 `/media/users/...jpg`；2. 打开 `/app/pages/me/index`；3. 查看个人信息卡头像 |
| 预期 | 展示新头像 |
| 实际 | 回退默认人形图标；DOM 无 `img`；网络请求为 `http://localhost/app/media/users/...jpg` 并失败 |
| 根因线索 | 媒体 URL 解析把 API base `/app/api/v1` 当作 origin，得到 `/app/media/...`，正确应为 `/media/...` |
| 影响 | 本轮新增的“头像编辑”在 H5 部署形态下不可见；小程序端未验证 |
| 证据 | [头像页面](attachments/2026-10-22-V3.1-全面模拟测试/ui-13-me-avatar-390.png)、[调试日志](attachments/2026-10-22-V3.1-全面模拟测试/avatar-display-debug.log) |
| 建议 | 修正 `resolveMediaUrl` 对 `/app/api/v1` 的 origin 归一化，或在 H5 直接使用同源根路径 `/media` |

### D-02 后端接受未来出生日期（一般）

### D-04 并发同幂等键请求返回 500（一般）

| 项 | 内容 |
|---|---|
| 复现步骤 | 5 个并发请求使用同一 `client_request_id` 创建问答会话 |
| 预期 | 1 个成功，其余 200 幂等重放或 409/1004 |
| 实际 | 1 个 200，4 个 HTTP 500/`code=1902` |

| 证据 | `api-run.log` `B-03` |
| 建议 | 捕获唯一键竞争异常并转换为 409/1004，或增加数据库级 `ON CONFLICT` 处理 |

## 9. 测试总结与建议

### 9.1 通过率与总体结论

| 统计口径 | 总数 | 通过 | 失败 | 阻塞 | 通过率 |
|---|---:|---:|---:|---:|---:|
| 本文可评审场景（用户端 + 运营端） | 67 | 59 | 5 | 3 | 88.1%（不含阻塞 92.2%） |
| 底层执行检查（84 API + 21 UI + 6 补充） | 111 | 101 | 7 | 3 | 91.0%（不含阻塞 93.5%） |

**总体结论**：核心用户链路（同意、档案、单域/家庭问答、风险拦截、测评、健康/笔记、提醒、工具、会员 mock 支付、资料编辑、退出/切换账号）和运营端登录/主要菜单均可用；但本轮存在 2 个严重缺陷、4 个一般缺陷、2 个轻微缺陷，且 V3.1 的三项外部门禁未关闭，**当前版本不应直接宣告正式发布**。

### 9.2 关键风险

1. **头像功能在 H5 不可见（D-01）**：本轮新增能力的核心展示链路失败，建议优先修复。
2. **宠物急症安全表达不足（D-05）**：即使受专家签署门禁影响，模板层也应强制就医引导与兽医免责声明。
3. **输入校验与 PRD 不一致（D-03/D-06）**：短问题可提交、长问题被 500 字截断，均与 AC-F4-01-1 不符。
4. **并发幂等返回 500（D-04）**：串行幂等正常，但并发场景会产生服务端错误。
5. **外部门禁未关闭**：分级规则专家签署、危机渠道号码核验、订阅消息模板报备、专题包专家双签，均导致对应功能无法按 PRD 全量验收。
6. **真实模型与真机未验证**：`LLM_MOCK=true` 下回答为模板/缓存内容，不能代表真实模型质量；微信小程序真机、真实支付、订阅消息也未覆盖。

### 9.3 后续建议（按优先级）

**P0（发布前必须）**

- 修复 D-01：统一 H5 媒体 URL 解析，确保 `/media/...` 同源直达；补充头像上传后的 E2E 回归。
- 修复 D-05：在宠物急症模板中强制“尽快就医/执业兽医”提示；完成分级规则专家签署后回归红/黄/绿全档位。
- 关闭 V3.1 外部门禁：渠道号码核验、分级规则签署、订阅模板报备、专题包双签。

**P1（本轮修复）**

- 修复 D-02：服务端校验未来出生日期。
- 修复 D-03/D-06：前后端统一 5–2000 字约束。
- 修复 D-04：并发幂等键冲突转为 409/1004，禁止 500。
- 修复 D-07：更新 `init_db.py` 表数量断言并纳入部署冒烟。

**P2（体验与工程）**

- 修复 D-08 favicon 404。
- 补充真实 LLM、真实微信登录/支付、订阅消息、报告导出、退款对账、安全 Agent 故障注入的专项测试。
- 增加 Firefox/Safari 与微信小程序真机兼容性回归。

### 9.4 测试范围声明

本轮已实际覆盖：用户端 H5 首启/首页/档案/问答/测评/健康/笔记/提醒/工具/会员 mock/权利/资料编辑/账号管理；运营端登录/MFA/知识库/日志/反馈/举报/风险/权利/渠道/分级/配置/审计/专题/工具/商品/退款/提醒统计；多智能体三 Agent 扇出、安全置顶、SSE 帧序与风险拦截。
