## 3. 多智能体协作功能验证

**PRD 定义**：3 个领域 Agent（child / pet / safety）+ 1 个编排器 + 1 个风险控制服务（V3.0 R6）；V3.1 §5.1 将问答路由升级为「先拦、再分档、后回答」三态。

### 3.1 协作链路实测（family 入口，SSE 流式）

实测请求：`entry=family` + 问题「孩子追猫，猫哈气怎么办」（新用户新题，避开答案缓存），SSE 关键帧：

```
event: started
data: {"sequence":1,"render_order":["safety","child","pet"],"first_packet_ms":...}

event: section_done
data: {"section_key":"safety","title":"安全提示","pinned":true, ...}     ← 安全分节置顶
event: section_done
data: {"section_key":"child","title":"育儿建议", ...}
event: section_done
data: {"section_key":"pet","title":"宠物养护建议", ...}

event: completed
data: {"status":"done","agents_involved":["child","pet","safety"],
       "disclaimer_id":"DISCLAIMER_V1","ai_generated_label":"AI_GEN_LABEL_V1",
       "quota":{"used":1,"limit":4}}
```

### 3.2 协作环节对照表

| 协作环节 | PRD 要求 | 实测结果 | 结论 |
|---|---|---|---|
| 编排与并行调度 | 复合场景调度 3 个领域 Agent（G-3） | `agents_involved=["child","pet","safety"]`，三节并行产出 | ✅ 通过 |
| 渲染顺序 | 安全分节置顶（GR-4） | `render_order=["safety","child","pet"]`，safety `pinned=true` | ✅ 通过 |
| 不可改写字段服务端注入 | 免责/AI 标识不经 LLM（GR-5） | `disclaimer_id` / `ai_generated_label` 服务端下发 | ✅ 通过 |
| 引用必须来自检索 | 无命中置专业咨询提示（GR-6） | pet 节输出「当前未匹配到知识库条目…请咨询专业人士」 | ✅ 通过 |
| 风险控制服务（N2） | 命中即阻断、正文为空（GR-1/2） | 三组高危输入全部 `blocked` 帧 + 无正文 + 伴随渠道卡 | ✅ 通过（D1 修复生效） |
| **三态路由（V3.1 §5.1）** | 风险放行后命中分级规则 → 规则引擎定档 | **未实现**：SSE 契约无 `triage` 对象，急症类放行问题（如 3 月龄发热）直接进入常规生成 | ❌ **未实现**（RQ-06，上线阻塞项） |
| 单活跃会话 | 第二条 409（GR-15） | 流式进行中创建第二条 → `409 code=1203「已有一个进行中的问答会话」` | ✅ 通过（上轮未测项本轮补测） |

**结论**：多智能体编排/聚合/安全置顶/服务端注入/风险拦截链路**完整可用且 D1 修复有效**；但 V3.1 要求的「分档」层（RQ-06 规则引擎）尚未建设，协作链路仍为 V3.0 的「二态路由」。

## 8. 缺陷清单

### N1 【严重】商品种子数据残留旧品牌名「小光景」，对外接口下发

| 项 | 内容 |
|---|---|
| 严重程度 | **严重**（违反品牌更名硬约束：对外展示不得保留「小光景」） |
| 违反条款 | 项目硬约束「所有对外展示文案必须使用 Babe宝伴，不得保留旧品牌名」；V3.1 RQ-02 文案合规 |
| 复现步骤 | ① `POST /auth/dev-login` 取 token；② `GET /api/v1/billing/product` |

| 影响 | 会员购买页对外展示旧品牌商品名（前端展示名来自该数据）；10-19 的 338 处文案更名未覆盖 DB 种子数据 |
