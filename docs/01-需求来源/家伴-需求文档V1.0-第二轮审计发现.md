## 一、内部矛盾与自相冲突

### A1【S1】风险预警 Agent 的执行位置在三处定义互相冲突（流程图与主流程把扫描排在调度之后）
- **依据**：正文三处要求"最先执行"——line 506「不受其他 Agent 结果影响，**优先执行**（在任何 Agent 之前运行）」；line 569 表 4.1 触发条件「**所有输入，先于一切执行**」；line 853 C-16「风险预警 Agent **必须优先于其他所有 Agent 执行**｜架构硬约束」。line 619 4.4 执行顺序「风险预警 Agent →（未命中时）中枢调度 Agent → 领域 Agent 并行推理 → 中枢汇总」。但 5.1 主流程：步骤 5「用户选择路径：方案 A：单独提问幼儿养育问题 →**调度** 0-6 育儿 Agent」（line 636-639），步骤 7 才是「**【风险预警 Agent 优先扫描输入内容】**」（line 641）；5.4 流程图 line 692-700 为 `D -- A 育儿问题 --> E[调度 0-6 育儿 Agent]` … `E --> I[风险预警 Agent 优先扫描]`，即先调度、后扫描。
- **影响**：研发按 5.1/5.4 实现会先做意图分类、档案读取甚至预热下游 Agent，高危输入在扫描前已进入调度链路，与 line 504「一旦命中：直接阻断内容生成，不输出任何回答文本」及 11.1 清单 10（line 919）矛盾；测试按第 4 章与第 5 章会得到两个相反结论；同时产生无谓的模型调用成本。
- **建议改法**：统一为「收请求 → 风险扫描（纯输入侧、不读档案）→ 通过后中枢调度」。具体：① 5.1 步骤改为 6 → 风险扫描 → 用户路径选择 → 调度；② 流程图把 `I/J` 前置到 `D{用户选择路径}` 之前（`A-->I-->J--否-->D`）；③ 4.4 增一行「风险扫描位置：先于中枢调度，且不得读取档案字段」；④ US-L1 增验收项「同一 request_id 下，日志中不存在早于风险判定时间的领域 Agent 调用记录」。

### A3【S1】单 Agent 响应 ≤8s 与 4.4 超时阈值「单 Agent 12s / 整体 15s」算术上不可同时成立
- **依据**：line 729 NFR-2.1「≤8s（…【假设】为首包 ≤3s、完整响应 ≤8s，采用流式输出）」；line 269 US-D1 验收 5「单 Agent 问答响应 ≤8s（详见 NFR-2.1）」；line 922 验收清单 11「单 Agent 响应 ≤8s，多 Agent ≤15s（以 P95 口径统计）」；但 line 623 超时阈值「【假设】单 Agent **12s**、整体 15s」。全文无延迟预算分解表。

- **建议改法**：① 明确 P95 只用于"用户可感知完成时间"，超时阈值不构成 SLO，不得与验收门槛混用；② 6.2 增「端到端延迟预算表」，建议：风险扫描 ≤300ms、调度 ≤500ms、领域 Agent 并行 ≤8s、汇总+过滤 ≤3s、落库+返回 ≤700ms，合计 ≤12.5s 留余量；③ 超时阈值改为「单 Agent 硬超时 9s（超过即降级）、整体硬超时 13s」，与验收门槛同向；④ NFR-2.1 补「多 Agent 场景首包 = 最慢被调 Agent 的首包，不叠加中枢汇总时间」。

### A4【S1】流式输出与「结构化 JSON + 收齐后汇总校验 + 输出侧过滤不可绕过」互斥，且流式协议未定义

### C2【S1】100% 拦截率不可达，且与"漏报兜底""误报申诉"三项要求互相牵制
- **依据**：line 150 场景 4「拦截率 **100%**」；line 919 验收清单 10「风险预警 Agent 对高危样本集 **100% 拦截**且不输出任何内容」；line 81 G-4「高危样本**召回率**、拦截后引导弹窗 **100% 触达**」（两个不同性质的指标并列为 100%）。同时 line 886 自认「风险漏判…需定义漏报兜底（如语义模型 + 人工抽检）」、line 885「误报的用户申诉入口与人工复核」、line 1018 Q-12「误报与漏报如何处理？」、line 808「需标注集评估」。

### C3【S1】7.3 的"风险拦截率"分子分母量纲不匹配，指标本身无意义；且假设指标缺埋点支撑
- **依据**：line 808「风险拦截率 = `qa_risk_block` 次数 / 含高危样本的提问数（需标注集评估）」——分子是线上真实拦截事件次数，分母是离线标注集样本数。而 line 91 真正想看的假设指标「高危输入拦截后，用户**离开高风险追问**的占比 ≥90%」在 7.2 埋点表（line 783-799）中无支撑事件（`qa_risk_block` 只带"命中类别"）。
- **影响**：两个不同总体相除的结果可能 >100% 也可能接近 0，无法用于任何决策；"拦截后行为"这一最有价值的指标无数据来源。
- **建议改法**：拆三个口径：① 召回率（离线）= 标注集中被拦截的高危样本数 / 标注集高危样本数；② 线上拦截量与拦截率 = `qa_risk_block` 次数 / `qa_submit` 次数（仅作趋势监控，不等价于召回率）；③ 拦截后行为 = 需新增埋点 `qa_risk_block_followup`（参数：`blocked_category`、`next_action`：转向非高风险提问/离开会话/重复提交/求助渠道点击）与 `session_end`；同时把 line 91 的"离开高风险追问"定义清（是"离开会话"还是"转向非高风险提问"）。

### C4【S1】指标口径三处不一致：测评完成率、付费转化率、7 日留存的分母定义互相打架
- **依据**：line 88「测评完成率 ≥60%（**进入测评页的用户**中完成提交的比例）」vs line 805「`assessment_complete` **次数** / `assessment_start` **次数**」（用户数 vs 事件次数；且"进入测评页"与 `assessment_start` 不一定是同一时刻）；line 90「**免费用户** → 会员付费转化率 ≥2%」vs line 807「首次 `pay_success` 用户数 / **新增用户数**」（分母不同，且未定义新用户统计窗口）；line 87「新用户 7 日留存 ≥25%」vs line 804「第 7 日回访用户数 / **当日**新增用户数」（"当日"未定义，cohort 口径缺失）。

## 四、合规与平台风险缺口

### D1【S1】缺少"AI 生成合成内容标识"要求（显式标识 + 隐式标识）
- **依据**：全文无"标识"字样（已核对 grep 无匹配）；line 196 只要求分享图片含免责声明；line 719 NFR-1.2 只要求免责声明 100% 附着；line 393 US-H1-4 同。
