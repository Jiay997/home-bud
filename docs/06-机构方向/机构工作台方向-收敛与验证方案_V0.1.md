## 2. 收敛后的 MVP：一个闭环

```
机构员工录入客户情况 → 生成正式建议书 → 打印 / 签字 / 留档 → 机构存档
```

| 判断 | 内容 | 理由 |
|---|---|---|
| **保留** | ① 接待前录入（机构客户档案）② 事后出正式建议书 ③ 打印 / 签字 / 留档 | 三者构成一个完整闭环，缺一环机构就不付钱 |
| **缓做** | 客户离店后跟进 | 这是机构 **CRM 能力**（提醒、回访、复购），不是内容能力；会把产品拖成另一类产品 |
| **缓做** | 现场边聊边查（需求方本轮未勾选） | 需要移动端实时响应，成本高、非刚需 |
| **不做** | 家长档案与机构客户档案打通 | 需求方已选「各走各的」，打通会把同意链路与数据隔离复杂度抬一个量级 |

## 3. 行业取舍：先早教，宠物医院限定非诊疗线

| 行业 | 与现有内容的关系 | 合规压力 | 结论 |
|---|---|---|---|
| **早教（0–6 岁）** | 与产品主线 0–6 岁**完全吻合** | 轻 | **第一波** |
| 学科培训（6 岁以上） | 撞 NG-1（不上线 6 岁以上学科辅导），且受双减限制 | 重 | **不做** |
| 宠物医院（诊疗业务） | 产品明确只做科普、不做疾病诊断（NG-2） | 重（涉《动物诊疗机构管理办法》） | **不做** |
| 宠物医院（洗美 / 寄养 / 行为咨询等非诊疗线） | 内容吻合 | 中 | **第二波** |

> ⚠️ 需求方说的「早教 / 培训机构」必须拆开：**早教 = 0–6 岁 = Babe宝伴主场**；**学科培训 = 6 岁以上 = 直接撞 NG-1**。这一条必须回给需求方确认。

## 4. 对现有图纸意味着什么（新增项清单）

| 层 | 现状 | ③ 要新增 |
|---|---|---|
| 数据 | 34 张表全部挂在个人 `app_user` 上，无机构实体 | `org`、`org_member`、机构客户档案、交付文件记录 |
| 入口 | 小程序（C 端）+ 内部运营后台 | **机构工作台（Web）＝第三个入口**，不能塞进内部后台 |
| 权限 | PRD §16 五个内部角色（超管/运营/客服/育儿专家/宠物专家） | 机构管理员 / 顾问 / 只读审计，且**机构之间数据严格隔离** |
| 交付物 | `report` 长图（个人分享用） | **带机构抬头的 PDF 正式建议书**（可打印、可签字、可留档） |
| 签字效力 | 架构文档 §8.2 **T-6 未决**（电子签名是否满足留档） | 复用同一结论，先出结论再实现 |
| 计费 | `subscription` 个人月卡 | 机构席位 / 年费（**数值未验证**） |
| 合规 | 家长是用户，Babe宝伴是处理者 | 机构成为委托方，Babe宝伴转为**受托处理者**；`consent_record` 与 Q-31（监护人同意核验）需重做 |

**复用（不重造）**：问答链路、风险控制服务、知识库与检索、测评、报告渲染 —— 这些是现成资产。

## 5. 两个必须在设计阶段就锁住的口径

1. **交付物的措辞必须沿用 PRD §11.12 强制用词规范**。机构版很容易被叫成「评估报告」「发展诊断」，这会重新引入测评与诊疗风险。早教机构给的只能是**「养育参考 / 行为倾向参考」**类表述，并保留免责声明与 AI 生成标识。
2. **风险拦截链路不可为机构场景放宽**。机构员工若为「促成交易」诱导提问，不影响风险扫描前置与拦截后正文为空的既有验收口径。

## 6. 开工前置：先做付费验证（不写代码）

| 项 | 内容 |
|---|---|
| 方法 | 找 **1–2 家早教机构**，人工（不走产品）为它的**真实客户**出一份正式建议书 |
| 验证什么 | 机构是否愿意为「这份文件 + 出文件的过程」付钱、付多少 |
| 不做什么 | 不写代码、不建表、不进基线、不承诺排期 |
| 建议时限 | 2 周内出结论 |
| 通过标准 | 至少 1 家愿意签付费意向（金额随意，但必须是真的钱） |

> 没有这一步就投入开发，等于用 V1.0 的工期赌一个**没人验证过的付费假设**。
